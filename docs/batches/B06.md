## Urutan kerja dan QA setiap checkpoint

1. M15: bangun/test adapters, mapping, receipts, locks dan reconciliation pada synthetic fixtures.
2. QA M15 dry-run→backfill→crash/resume→same-source replay→owner checks; no real copy otomatis.
3. M16 hanya setelah approval/source-target/fresh backup gate: scoped real snapshot→private rehearsal build.
4. Lakukan second rehearsal delta+resume, verify files/grades/access/restore dan reviewer sign-offs.

Integration exit: Source records= mapped + approved historical-only + tracked quarantine; learner/state/file reconciliation exact; duplicate or absent source rows preserved, old staging public intact.

## Automation dan batas lanjut

M15 dapat backend verified dari complete synthetic tests, tetapi M16 tetap NOT_EXECUTED/BLOCKED_INPUT tanpa actual approved rehearsal. Tidak lanjut actual pilot dari synthetic success.

Authority gate: Explicit production read/export dan staging import scope, encryption/access/object copy, fresh backups/restore. Synthetic test PASS bukan izin menjalankan M16.

STOP jika: Unverified source/target, stale/corrupt backup, schema mismatch, critical ambiguity, missing proof, outbound side effect atau capacity pressure.

QA yang gagal memicu perbaikan+rerun dalam scope, bukan skip test atau otomatis lanjut dependency. Sesi/limit terputus → simpan checkpoint → verifikasi evidence/worktree saat resume. Tidak perlu memberi instruksi terpisah per M yang sudah masuk scope gelombang, tetapi izin operasi baru tetap diminta ketika diperlukan.
