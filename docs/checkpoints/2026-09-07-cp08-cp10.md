## Flow bisnis yang sekarang benar-benar berjalan

1. Operator lab membuat fixture identity/session setelah pre-v3 backup/restore proof. HTTP tidak memiliki bypass login, endpoint seed atau migration.
2. Admin membuat Class hanya dengan nama. Program/cohort merupakan label opsional; dua Class bernama sama tetap punya ID berbeda. Tidak ada prerequisite Batch/global Mentor.
3. Admin menambahkan beberapa Teachers dan Students. Satu enrollment stabil per user/Class, episode partisipasi terpisah, role assignment terpisah. Penambahan peserta oleh Teacher **belum diizinkan pada slice ini**.
4. Teacher hanya mengedit/publish Class dengan enrollment aktif dan role Teacher aktif. Student tidak membaca draft. Publish membutuhkan Teacher aktif; content-readiness belum tersedia.
5. End enrollment menutup episode dan mencabut role tanpa menghapus history. Rejoin memakai enrollment ID yang sama dengan episode baru. Published Class tidak boleh kehilangan Teacher terakhir melalui command end.
6. Admin mengarsipkan Class; read historis sesuai akses tetap tersedia, mutasi baru ditolak. Lifecycle terbatas DRAFT/PUBLISHED/ARCHIVED dan ACTIVE/ENDED; CLOSED/SUSPENDED/INVITED/groups/retake belum lengkap.
7. Setiap command memakai Idempotency-Key; payload berbeda pada key sama atau version stale ditolak. Authorisasi saat ini diperiksa sebelum replay. Domain, audit, outbox dan response command dicommit bersama; failure tidak boleh meninggalkan partial rows.

Entry point khusus `cmd/class-lab` hanya menerima cluster loopback baru yang marker-nya cocok. `cmd/api` tetap bootstrap: liveness 200, readiness 503, business routes 404. Business flow di atas **tidak** berarti service staging telah melayaninya.

## Residual risks and release blockers

1. Identity is checked from current DB state at request start, but strict **in-flight account/session revocation serialization is not guaranteed**. Do not claim immediate revocation fences until CP11/12 concurrency policy and tests exist.
2. Fixture-issued bearer sessions are not real provisioning/login. Cookie authentication is deliberately off; browser compatibility/CSRF semantics, identity authority/bridge, token lifecycle and last-admin invariants remain M04 work.
3. Teacher participant management, full capability registry, closed/suspended/invited states, grouping and retake policy remain incomplete. Publish currently checks active Teacher, not content readiness.
4. `internal/labdb` is a fixed additive synthetic fixture installer, not a general production migration engine. Receipt `restored` is a trusted local harness declaration supported by retained restore commands, not independent signed operator approval.
5. Outbox provides persistence/lease protocol, not a provider worker. Delivery is at-least-once; consumer dedupe and retained failure/dead-letter history are required before integration use.
6. CP07 source identity, provider exposure, least privilege, protected real backup and legacy security disposition remain open. Go development does not secure the currently deployed legacy service by itself.
