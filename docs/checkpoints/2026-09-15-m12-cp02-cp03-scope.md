# Scope freeze — M12-CP02 dan M12-CP03

Frozen before implementation. Backend Go only; exactly two sequential CPs. No CP04, historical import, frontend, shared/staging/production access, commit or push.

## M12-CP02 — entry and revision lifecycle

- Active Student identity determines its Class enrollment and active episode. A learner can keep at most one entry per published period and episode; caller cannot choose another learner/enrollment/episode.
- Save appends an immutable text revision plus optional ordered references to existing `AVAILABLE` private evidence owned by that learner in the same Class. It never overwrites a revision/file reference. Entry work is permitted only while server time is within the published period start–deadline window.
- Initial/repeated save yields DRAFT. Submit requires exact latest revision and expected state version; DRAFT becomes SUBMITTED. CP02 cannot produce review decisions. Submitted/accepted content cannot be silently edited.
- Student reads own entry. Active assigned mentor or site Admin may read for later CP03, but an unassigned/foreign Teacher, outsider, cross-Class actor or suspended participation cannot. Audit/outbox/state/revision/idempotency commit atomically.

Frozen cases: `TestSyntheticLogbookEntryLifecycle`, `TestSyntheticLogbookEntryBoundary`, `M12-CP02-entry-lifecycle`, `M12-CP02-entry-boundary`.

## M12-CP03 — scoped review and mentor provenance

- Only site Admin or the learner's current active personal mentor in the same Class may decide a SUBMITTED revision. Generic Teacher role, specialization/profile strings, previous mentor and self are not authority.
- Decision is `REVISION_REQUIRED` or `ACCEPTED`, with non-empty private feedback, exact submitted revision and expected state version. Competing decisions serialize on the entry and exactly one can succeed.
- After `REVISION_REQUIRED`, the learner appends a new immutable revision and submits again. Mentor reassignment history remains intact; each review state records the effective `mentor_assignment_id`, so a later mentor can review a later submission without rewriting old provenance.
- Review event, command receipt, audit and outbox commit atomically. No delete/update of revision or state history and no global account/other-Class mutation.

Frozen cases: `TestSyntheticLogbookReviewLifecycle`, `TestSyntheticLogbookReviewBoundary`, `M12-CP03-review-lifecycle`, `M12-CP03-review-boundary`.
