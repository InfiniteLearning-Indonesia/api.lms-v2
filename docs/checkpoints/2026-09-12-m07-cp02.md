## Capaian

- Additive schema `v3.content_revisions` dan `v3.content_revision_sources`; ancestry memakai composite Class/activity FK, revision number unik, state/time constraints, FK indexes dan partial published-availability index.
- Raw authoring source maksimal 64 KiB dipertahankan beserta SHA-256, tetapi runtime role hanya memperoleh `INSERT/UPDATE`, tanpa `SELECT/DELETE/TRUNCATE`.
- Canonical response memakai `SAFE_HTML`: UTF-8/control validation, normalisasi newline, HTML escaping, dan tidak pernah mengembalikan `raw_body`.
- Lifecycle dibatasi `DRAFT → PUBLISHED → WITHDRAWN`; update hanya untuk DRAFT dengan optimistic version.
- Timezone IANA divalidasi memakai embedded `time/tzdata`, sehingga tidak bergantung zoneinfo host/container. Untuk timestamp yang sama-sama terisi, urutan `available_from ≤ due_at ≤ cutoff_at` dijaga aplikasi dan constraint database.
- `due_at/cutoff_at` hanya berlaku untuk activity `ASSIGNMENT`; Student hanya melihat revision PUBLISHED yang sudah mencapai `available_from`.
- Semua command idempotent dan perubahan + audit + outbox berada dalam satu transaksi pendek. Tidak ada delete endpoint/cascade.
- Binary baru tetap dapat membaca schema CP01 sebelum CP02 terpasang, mendukung urutan rolling migration yang aman.
