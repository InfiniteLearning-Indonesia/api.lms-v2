## API and consistency policy

- Retain the CP01 GET. Add `POST /v3/classes/{class_id}/reports/grades/{learner_user_id}/pages` and `/exports` with strict JSON (12 KiB body), normal cookie/CSRF/origin authority and no query strings. No shared gateway authorization relaxation.
- Same active Class/learner and assigned Teacher/Admin or learner-self boundary as the report; no arbitrary learner filter. Only optional exact `grade_item_id` filter and `grade_item_id_asc` sort. Unknown fields, invalid IDs/sort and page sizes outside 1–50 fail closed.
- HMAC-SHA256 opaque cursor binds session hash, Class, learner, filter, sort, page size, last item ID, full canonical report snapshot SHA-256 and 10-minute expiry. Raw session never appears in cursor or logs. All pages reauthorize. Invalid/tampered cursor 400, foreign session/context 403; changed snapshot/expired cursor 409 requiring restart. No silent mixing across released-grade changes. A fresh random per-handler key is synthetic-runtime-only; restart invalidates cursors, and a shared stable key is a future deployment gate.
- Source report limited to 200 visible latest grade items (read at most 201 rows and return 413 when over limit). Pages max 50 rows; report/page/export output max 256 KiB. Oversize fails without partial output. These conservative bounds are explicit, not performance/load claims.
- Private CSV is generated synchronously in memory for the same bounded authorized report, with fixed safe download filename, `no-store`, no public URL/object or background delivery. Neutralize spreadsheet formula prefixes in user-controlled title cells. Each successful export request atomically commits one scoped audit row plus an isolated `reporting.audit.v1` outbox event before sending bytes. Audit action encodes exact learner ID and snapshot digest. Retries are repeatable reads and intentionally produce separate access audit entries; no exactly-once/idempotency claim.
- Reuse existing audit/outbox tables; no new DDL or shared data mutation. Fresh QA dependency migrations still require SQL/custom backup plus actual isolated restore. No database deletion, real provider, frontend, commit, push or deployment.
