## Capaian M06-CP01

- `FileAsset` mempunyai owner, Class, purpose `MATERIAL|EVIDENCE`, metadata terdeteksi, checksum, scan state, actor, dan lifecycle timestamp yang tervalidasi constraint.
- Object berada di root privat dengan locator acak 256-bit yang tidak diekspos API dan sengaja berbeda dari checksum client-visible. Path traversal, symlink, overwrite, dan file non-regular ditolak; setiap read memverifikasi ukuran serta SHA-256.
- Contextual capability berlaku di backend: SiteAdmin; Teacher Class; Student aktif hanya untuk evidence miliknya dan material pada Class published. Foreign Class/owner ditolak sebelum object write.
- Upload memakai idempotency key; asset, audit, outbox, dan response receipt commit atomik. Runtime role tidak memiliki `DELETE`/`TRUNCATE` dan relasi memakai FK/index eksplisit tanpa cascade.

## Capaian M06-CP02

- Upload menerima raw bounded body maksimal 2 MiB, filename aman, allowlist MIME tepat, dan verifikasi magic-byte/detected MIME. Tidak ada base64/public URL fallback.
- Semua bytes masuk quarantine terlebih dahulu. Threat menjadi `REJECTED`; scanner/provider error tetap `QUARANTINED`; hanya hasil `CLEAN` dapat dipromosikan `AVAILABLE`.
- Download memakai token acak short-lived yang hanya disimpan sebagai hash, terikat asset+user, TTL 1 detik–5 menit, serta dicek ulang policy sebelum dan sesudah object read. Retry selama TTL tetap diizinkan dan diaudit per delivery.
- Expired/foreign/unavailable grant gagal tertutup. Delivery sukses menghasilkan append-only access event, audit, dan outbox. Retry upload tidak membuat row domain ganda.
- `FixtureScanner` dan local object store hanya adapter QA. Provider malware scanner dan private object storage nyata tetap external gate, bukan diam-diam dianggap selesai.

## API slice

- `POST /v3/classes/{class_id}/files`
- `GET /v3/files/{asset_id}`
- `POST /v3/files/{asset_id}/scan`
- `POST /v3/files/{asset_id}/download-grants`
- `GET /v3/file-downloads/{token}`

Seluruh route memakai verified cookie identity dari gateway; bearer fallback dan query-token ditolak. Mutation memakai CSRF, bounded body, strict JSON pada grant, `Idempotency-Key`, `no-store`, `nosniff`, serta safe content disposition/referrer policy.
