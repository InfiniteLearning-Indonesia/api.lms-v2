## M12-CP02 — entry dan revision lifecycle

Schema additive di `internal/labdb/m12.go` memisahkan `logbook_entries`, revision konten immutable, referensi evidence file, event state append-only, dan receipt idempotency. Satu entry diikat unik pada period + enrollment episode; FK komposit menjaga Class/period/enrollment/episode/file tidak silang konteks. Indeks tersedia pada seluruh jalur FK/read utama. Trigger DB menolak update histori, learner yang bukan Student aktif, enrollment suspended/revoked, episode berakhir, period bukan publik/di luar server-clock window, urutan revision/event yang lompat, dan file yang bukan milik learner atau bukan `AVAILABLE/EVIDENCE`. Runtime role tidak mempunyai `DELETE/TRUNCATE`.

`internal/logbook/entries.go` memperoleh identity dari bridge, bukan body request; enrollment dan episode diturunkan server-side. `save` menambahkan revision baru dan event `DRAFT`, sedangkan `submit` memakai exact revision + expected version dan membuat event `SUBMITTED`. Revision lama dan file reference tidak ditimpa. Read hanya untuk site admin, learner aktif pemilik, atau personal mentor aktif saat ini pada Class tersebut. Idempotency lock, state mutation, audit, outbox, dan response receipt berada dalam satu transaksi.

`internal/logbook/http.go` menyediakan kontrak QA backend untuk create/revise, exact submit, dan scoped read dengan auth gateway, CSRF, strict JSON, body limit, no-store, method/path allowlist, serta server-generated ownership. Endpoint ini masih hanya di-wiring melalui `cmd/identity-lab` untuk harness sintetis, belum ke `cmd/api` shared runtime.

## M12-CP03 — review dan mentor provenance

`internal/logbook/reviews.go` hanya menerima keputusan `REVISION_REQUIRED` atau `ACCEPTED` terhadap exact submitted revision/version. Reviewer bukan role Teacher global: selain site admin aktif, hanya personal mentor yang assignment-nya masih efektif, enrollment Teacher-nya aktif, role tidak revoked, dan access tidak suspended. Self-review, Teacher generik, mentor lama, dan foreign Class ditolak. Review memakai compare-and-swap di row lock sehingga dua keputusan bersaing menghasilkan tepat satu keberhasilan.

Setiap review menyimpan `mentor_assignment_id`, feedback, actor, revision, version, dan timestamp dalam event immutable. Setelah `REVISION_REQUIRED`, learner membuat revision DRAFT baru lalu resubmit; reassignment mengakhiri assignment lama tanpa menghapus event review sebelumnya. Audit, outbox, event, dan idempotency receipt review tetap atomic. Pemeriksaan authority juga ada pada trigger DB sebagai defense-in-depth, termasuk active identity untuk site admin.
