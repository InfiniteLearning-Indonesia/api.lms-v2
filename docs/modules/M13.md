## Tujuan dan scope

Provider failure/retry tidak merusak transaksi akademik atau memberi nilai lulus palsu.

- Prioritas/kompleksitas: **P1/P2 / Medium**; owner/reviewer belum ditetapkan.
- Dependency: M03/M04/M06; M08/M09 untuk AI; events M05/M10–M12 sesuai use.
- Coverage pekerjaan: Delivery/job attempts, bounded retries, notification sinks/preferences, secret handling dan reviewed AI suggestions.
- Di luar scope: Tidak frontend AI/settings, sending ke production recipients saat QA, atau jaminan exactly-once provider tanpa support.
- Area file: `internal/integrations/`, `internal/notifications/`, `cmd/worker/`. Path Go/QA adalah usulan, belum file implementasi.
- Referensi: [ImplementationPlan §8/M13](../../../../ImplementationPlan.MD), serta §3–7 untuk domain/security dan §9–16 untuk data/test/cutover.

## Data safety, exit dan fallback

- Gate data: No-delete job receipts/attempts; credential rotation separate approved action; mocks default for all outbound QA.
- Fallback: Integrations OFF/manual academic flow remains; failed attempts retained.
- Exit backend: seluruh D dan shared gates applicable terverifikasi pada source/test/contract hash dan environment yang tepat. Critical failure/skip/blocker menghalangi kelulusan.
- External gate: approval operasional tetap terpisah bila menyentuh environment nyata; backend QA tidak memberikan izin deployment.
