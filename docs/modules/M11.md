## Tujuan dan scope

Attendance/izin/SP tetap ada tetapi hanya memengaruhi participation Class yang tepat.

- Prioritas/kompleksitas: **P1 / Large**; owner/reviewer belum ditetapkan.
- Dependency: M05/M06, access M04, audit/outbox M03; M10 untuk outcome integration.
- Coverage pekerjaan: Meetings/calendar exceptions, attendance revisions, approval lifecycle/private proof dan Class-local SP.
- Di luar scope: Tidak attendance UI, request=approved, global suspension otomatis atau infer absent tanpa evidence.
- Area file: `internal/attendance/`, meeting/permit/discipline APIs. Path Go/QA adalah usulan, belum file implementasi.
- Referensi: [ImplementationPlan §8/M11](../../../../ImplementationPlan.MD), serta §3–7 untuk domain/security dan §9–16 untuk data/test/cutover.

## Data safety, exit dan fallback

- Gate data: Backup before mapping; preserve historical statuses/unknown reviewer, no fabricated approval or deletion.
- Fallback: Keep unallocated legacy evidence restricted; affected Class cannot cutover with unresolved required attendance.
- Exit backend: seluruh D dan shared gates applicable terverifikasi pada source/test/contract hash dan environment yang tepat. Critical failure/skip/blocker menghalangi kelulusan.
- External gate: approval operasional tetap terpisah bila menyentuh environment nyata; backend QA tidak memberikan izin deployment.
