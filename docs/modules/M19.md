## Tujuan dan scope

Menambah fitur bernilai setelah core stabil tanpa menjadikan seluruh Moodle wajib dibangun.

- Prioritas/kompleksitas: **P3 / Large per approved feature**; owner/reviewer belum ditetapkan.
- Dependency: Core stable; feature selection, ADR/threat model and explicit budget/scope approved.
- Coverage pekerjaan: Candidate backend templates, explicit cohort sync, richer groups, quiz/attempt/question bank atau standards integrations.
- Di luar scope: Tidak seluruh candidate sekaligus, frontend features, optional work as shortcut around pending migration/security gates.
- Area file: Feature-specific `internal/` modules dan OpenAPI ditentukan setelah selection. Path Go/QA adalah usulan, belum file implementasi.
- Referensi: [ImplementationPlan §8/M19](../../../../ImplementationPlan.MD), serta §3–7 untuk domain/security dan §9–16 untuk data/test/cutover.

## Data safety, exit dan fallback

- Gate data: DEFERRED until scope frozen; no migration/external integration activation implied by brief.
- Fallback: Feature flag OFF; core flows unaffected; preserve feature data/history if disabled.
- Exit backend: seluruh D dan shared gates applicable terverifikasi pada source/test/contract hash dan environment yang tepat. Critical failure/skip/blocker menghalangi kelulusan.
- External gate: approval operasional tetap terpisah bila menyentuh environment nyata; backend QA tidak memberikan izin deployment.
