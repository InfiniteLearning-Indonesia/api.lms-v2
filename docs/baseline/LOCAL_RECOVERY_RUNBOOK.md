# Small local recovery QA — no staging credentials

17 November 2026. [Scope](../checkpoints/2026-11-17-local-recovery-scope.md), [implementation/results](../checkpoints/2026-11-17-local-recovery.md). Supports M01 / DLV-04 local recovery preparation. Not a production source adapter or staging runtime.

## Local Go operations

The [baseline-package CLI](../../cmd/baseline-package/main.go) has two explicit new modes. They never load `.env`, connect to a database or print plaintext:

- **`--seal-only`**: strict JSON `SealPackageArtifactRequest` (version/package/tool/identity_path/role/source_directory/source_name/plain/recipient/custody_ref). Reads only a private single-linked local file outside the artifact directory, binds source/snapshot/target/schemas/role/name/plain digest, and uses exclusive protected encrypted output + actual readback. Cipher budget is capped by the declared role's dump/SQL/object capacity. Other artifact ciphertext hashes may still be pending; this is per-file production, not whole-package/source verification.
- **`--recover-only`**: strict JSON `RecoverPackageArtifactRequest` (version/authentication/role/directory/name). Whole-package auth first, then selected anchored ciphertext authentication **before** output creation. Creates a new protected plaintext file outside the artifact directory, performs authenticated second-pass transfer, sync/hash/readback/protection/identity checks and returns `OFFLINE_ARTIFACT_RECOVERED_NOT_AUTHORIZED`.

Recovery emits no plaintext to stdout. During a failed second pass a private partial plaintext file may remain: no success receipt, overwrite, rename, promotion or deletion. Filename alone is never validity. Trusted immutable operator-controlled host/input required; arbitrary blocking I/O cancellation, local administrator attacks, crash durability and long-term archive recovery are not all proved by this slice.

Files/keys must pass actual host checks from [protected-package contract](PROTECTED_PACKAGE_RECOVERY.md). Key remains outside artifact/recovery directories. Recovery report authentication/protection may become true, but actual DB restore, real baseline, independent custody and operational authority remain false. Do not execute a recovered SQL file merely because decryption succeeded.

## One owner-terminal command

```powershell
D:\Projects\lms-v2\backend-v3\backend-go\qa\RUN_LOCAL_RECOVERY_QA.cmd
```

Wrapper calls [qa.local_recovery_run](../../qa/local_recovery_run.py) with explicit **new-local-synthetic-cluster acknowledgement** and installed PostgreSQL 18 bin directory. No DSN/env/existing-cluster/file-input parameter is accepted. Adjust only the local PostgreSQL binary directory if installed elsewhere. This runner is for an ordinary terminal of the key/directory owner; do not loosen ACLs or add sandbox access.

Pipeline:

1. Existing storage admission + verified source backup, cached-tool proof, same-tree CLI build, **nine exact actual crypto cases**, 81 exact default Go cases and vet. `--no-download` now skips both tool installation and project dependency downloads; cache missing means STOP, not network fallback.
2. Native PG18 tool/version checks, second storage lock/admission, one new run under canonical `lms-v3-qa-artifacts/<UTC>-postgres-lab-<id>`, exact **95 Python ops** before any database creation. Current source checked throughout.
3. New loopback cluster only: generated synthetic SCRAM credentials, explicit 127.0.0.1/ephemeral port, low connection/shared-buffer/WAL settings. Verify actual `data_directory` before role/database mutations. Generated app role is NOSUPERUSER/NOCREATEDB/NOCREATEROLE/NOBYPASSRLS. Bootstrap superuser belongs solely to the new cluster.
4. Create fixed new source/custom-target/SQL-target databases. Empty-prestate custom+SQL backups each restored into a **new proof database** and catalog-compared before fixture DDL/target restore. No `--clean`, `--create` restore, DROP/DELETE/TRUNCATE or target overwrite.
5. Tiny synthetic Class/learner/enrollment/marker fixture: keys/FKs/unique/indexes/serial sequences, six rows. Export one consistent custom archive and render SQL **from that archive**, rather than doing two independent live dumps. Validate source fingerprints unchanged while exporting.
6. Seal custom/SQL/one synthetic object into a protected age package, finalize/hash private metadata, authenticate via CLI, recover all three payloads into new private files and compare byte hashes.
7. Restore recovered custom into one empty target using `pg_restore --single-transaction --exit-on-error --no-owner --no-acl`; restore recovered SQL into a second empty target with psql `--single-transaction` and `ON_ERROR_STOP`. Source is generated by this same fixed fixture, not an arbitrary user dump.
8. Compare catalogs, columns/defaults, FK/unique constraints, indexes, all rows and sequence values against source; compare one recovered object byte-for-byte. Deliberately invalid FK insert must fail with SQLSTATE 23503 and preserve fingerprints. Explicit invalid PK avoids advancing a serial sequence as a side effect of the negative test.
9. Stop only this new cluster, prove `shut down` using native control data and no PID marker, retain all evidence/backups/data; emit exact ten-case result. A failed stop is not accepted.

The ten DB-stage IDs are frozen in [M01-LOCAL-RECOVERY.json](../../qa/manifests/M01-LOCAL-RECOVERY.json). Only exact all-PASS plus unchanged source can produce `PASS_SYNTHETIC_ONLY` / `actual_restore_verified=true`, scoped solely to this fixture. Missing/skipped/failed cases and compile-only evidence never pass.

## Boundaries and cost

- The existing large LMS dependency journey is **not** rerun. Fixture is four small tables, three empty prestate proof databases and two restored targets, plus one opaque object; it is not a full LMS migration/mapping or arbitrary-scale recovery proof.
- Existing storage policy remains: managed global budget/reserve/free-space checks; per-run growth guards. PG phase has a 20-minute command budget with separate bounded shutdown; initial crypto gate has its own 30-minute budget, and admission/backup may take additional time. These are checks/timeouts, not an OS write quota.
- A new `retention-pin.json` explicitly holds this small recovery profile pending policy/acceptance review. **No retention disposal hook or historical cleanup runs.** Raw cluster/backups remain under the counted canonical root. Do not repeatedly create identical clusters; reuse reviewed evidence when source/scope are unchanged. The pin/new profile is not automatically eligible for existing three-cluster disposal policy.
- Keys, source dumps and recovered plaintext live in restrictive new private subdirectories; only generated synthetic data, never live PII. Bootstrap credential is private; age key generation is not logged. Real provider/legacy/job processes never start. `.env`, stage DBs, source credentials and old clusters are untouched.
- Source-role/TLS/custody labels in package metadata are **fixture declarations**, not independent observations: actual test database transport is loopback SCRAM with ssl=off and an app-owned source. This does not satisfy production TLS/least-privilege export gates.
- SQL/custom/object backup completeness for production, global roles/tablespaces, RLS/session lifecycle, multi-object archives/buckets, foreign providers and schema/version drift are outside this small fixture.
- Existing 24-hour fresh-package rules remain. Historical disaster recovery requires a separate reviewed contract; never alter timestamps to force acceptance.

PostgreSQL semantics used: [custom archive/SQL rendering and executable-dump warning](https://www.postgresql.org/docs/18/app-pgrestore.html), [consistent pg_dump export](https://www.postgresql.org/docs/18/app-pgdump.html), [psql single-transaction requires command/file options](https://www.postgresql.org/docs/18/app-psql.html). SQL through stdin is explicitly `--file=-`; quiet mode avoids command tags contaminating fingerprint results. No snapshot from an untrusted source is executed by this fixture runner.

## How to read failures

If native crypto fails, DB creation is never reached. If initdb fails (including fatal stderr despite exit 0), retain its partial files via `--no-clean` and stop acceptance. DB failure keeps receipts and stopped cluster; failure to stop requires operator review, never deleting/killing an unrelated cluster. Preparation failures before startup may leave a creation record/pin without final summary: this is incomplete evidence, not PASS.

Return the final status/run ID for source/case/backup/parity review. Until actual native recovery passes, status is IMPLEMENTED_PENDING_NATIVE_QA, actual restore NOT_RUN. Do not edit source while the command runs or point it at staging. No release, commit, push or traffic authority is inferred.
