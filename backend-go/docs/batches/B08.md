## Urutan kerja dan QA setiap checkpoint

1. Pilih feature dan non-goals; brief M19 saat ini hanya candidate gates, bukan seluruh scope implementasi.
2. Perluas D/T IDs menjadi feature-specific cases dan freeze denominator sebelum coding.
3. Implement selected backend slice, backup additive schema changes, QA dan regression dependency.
4. Feature enablement/release memerlukan review; candidates lain tetap deferred.

Integration exit: Template structure-only, explicit cohort enrollment atau quiz attempt/evidence boundaries sesuai feature yang benar-benar dipilih.

## Automation dan batas lanjut

M19 DEFERRED adalah status sah dan bukan blockers untuk core release. Jangan mengarang coverage100% dari lima template gates.

Authority gate: Explicit feature selection/scope; external integrations/data changes memerlukan permission tersendiri.

STOP jika: Tidak ada selected feature, generic-only test matrix, scope creep meniru seluruh Moodle atau critical core risk belum tertangani.

QA yang gagal memicu perbaikan+rerun dalam scope, bukan skip test atau otomatis lanjut dependency. Sesi/limit terputus → simpan checkpoint → verifikasi evidence/worktree saat resume. Tidak perlu memberi instruksi terpisah per M yang sudah masuk scope gelombang, tetapi izin operasi baru tetap diminta ketika diperlukan.
