## Capaian dan dependency

Environment source/target benar, backup dapat direstore, dan vulnerable backend legacy mempunyai containment evidence.

Paket: [M00](../modules/M00.md), [M01](../modules/M01.md), [M02](../modules/M02.md). Dependency: Tidak ada gelombang sebelumnya; akses/environment/CA dan otorisasi patch legacy harus tersedia sebelum operasi nyata.

## Urutan kerja dan QA setiap checkpoint

1. M00: inventory dan fingerprint read-only; QA operator/manifest lalu checkpoint.
2. M01: backup source/target dan isolated restore setelah approval; QA restore/reconciliation lalu checkpoint.
3. M02: containment backend legacy pada repo tepat, QA negative/API/native legacy. Companion frontend security dicatat external, tidak diimplementasi dalam scope backend.
4. Jalankan cumulative safety checks; status backend, deployment dan external security tetap dipisah.

Integration exit: Wrong environment/backup blocks all writes; verified backup→reviewed legacy containment; actual deployment proof terpisah dari test pass.

## Automation dan batas lanjut

Go design/unit work di B02 boleh sebagai scope terpisah jika hanya local-synthetic dan baseline yang dibutuhkan tersedia. Itu tidak menandai M00–M02 atau B01 selesai.

Authority gate: Production read/export, backup destination, target restore/create dan legacy patch/deploy harus diotorisasi terpisah sesuai operasi. Frontend security companion memerlukan pekerjaan terpisah.

STOP jika: Unknown source/target, CA failure, incomplete backup/restore, known Critical path tanpa containment, atau kebutuhan frontend/ops di luar scope.

QA yang gagal memicu perbaikan+rerun dalam scope, bukan skip test atau otomatis lanjut dependency. Sesi/limit terputus → simpan checkpoint → verifikasi evidence/worktree saat resume. Tidak perlu memberi instruksi terpisah per M yang sudah masuk scope gelombang, tetapi izin operasi baru tetap diminta ketika diperlukan.
