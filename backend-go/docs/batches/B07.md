## Capaian dan dependency

Backend siap dan, setelah external gates diotorisasi, dapat beralih per migration unit dengan satu writer serta recovery yang tidak kehilangan karya baru.

Paket: [M17](../modules/M17.md), [M18](../modules/M18.md). Dependency: M02/M14/M16 approved; real frontend/identity compatibility, pilot scope, ops/data/security sign-off dan maintenance readiness.

## Urutan kerja dan QA setiap checkpoint

1. M17 backend preparation: implement/fault-test owner/fence/drain/final-delta sequencing di lab; QA tidak auto-route traffic.
2. Tahan actual pilot sampai frontend dan approval gates terpenuhi; record first v3 write setelah authorized switch.
3. M18 backend operations: alerts/access/restore/archive/wave guards; QA tiap wave readiness.
4. Actual rollout hanya setelah pilot observed/accepted, fresh backup dan wave-specific approval. Setiap wave evidence terpisah.

Integration exit: Legacy writer stays denied after switch; Go denies legacy-owned units; switch failure→both fenced; post-first-write outage→hold/forward fix, bukan route ke stale legacy.

## Automation dan batas lanjut

Backend-first deliverables dapat diuji di isolated lab; B07 full completion tetap BLOCKED_EXTERNAL sampai user-facing readiness dan rollout nyata terbukti.

Authority gate: Frontend actual readiness dan authorization untuk tiap real pilot/rollout operation. User communication/support/maintenance window wajib.

STOP jika: Frontend pending, unscopable old writer, identity revocation gap, missing final backup/delta, unauthorized owner flip atau failed observation.

QA yang gagal memicu perbaikan+rerun dalam scope, bukan skip test atau otomatis lanjut dependency. Sesi/limit terputus → simpan checkpoint → verifikasi evidence/worktree saat resume. Tidak perlu memberi instruksi terpisah per M yang sudah masuk scope gelombang, tetapi izin operasi baru tetap diminta ketika diperlukan.
